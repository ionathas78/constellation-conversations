# Operations and design decisions

## Hosting

GitHub Pages is the intended deployment target, with Actions as the publishing source. The workflow only uploads generated `dist/`; sources and dependencies are not published. `BASE_PATH` scopes all asset and publication paths for project hosting. For a custom domain, set `BASE_PATH` empty and configure DNS/Pages separately. No external database or service is required.

The GitHub integration can edit repository contents and inspect Actions but does not expose a Pages settings mutation. If Pages has not been enabled and no authenticated settings browser is available, the repository owner must select **Settings → Pages → Source: GitHub Actions**. A configured workflow is not proof of deployment; verify its successful deploy job and open its reported URL.

## Security

Conversation data is treated as text. Ajv rejects unknown fields and invalid structures; semantic validation checks speaker references, dates, IDs, story targets, dice expressions, and local assets. Markdown raw HTML is disabled, links/images pass URL checks, strings in attributes and metadata are escaped, emoji use registry assets, and math rendering disables trusted commands. Story HTML is generated by the same safe Markdown renderer at build time and embedded as escaped data. There are no content-authored scripts.

A meta CSP denies arbitrary script sources, plugins and cross-origin fetches; frames are limited to two media providers. Inline styles are permitted for speaker accents and static math output. GitHub Pages cannot set arbitrary response headers, so frame-ancestors and server-side protections are not claimed. External images and native media are author-chosen HTTPS resources and can contact their hosts; prefer local assets for privacy and resilience. Embeds are click-to-load. Downloaded file formats and author-provided SVGs require normal repository review: only trusted maintainers should add assets. This is a publishing pipeline, not a public arbitrary-file upload service.

Dependency versions are pinned and a lockfile is committed. Run `npm audit` periodically and update build tools when security fixes are available. Actions use official major-version tags; repositories with stricter supply-chain requirements can pin action commit SHAs.

## Accessibility and fallbacks

Semantic landmarks, a skip link, text speaker attribution, labelled controls, native buttons, visible focus, keyboard-operable disclosures and dialog, local video captions, math MathML, reduced-motion assets, contrast-conscious themes, and overflow-safe code/tables are included. Without JavaScript: transcripts, attachments, ordinary image links, provider links, library links, native media and the complete story map remain readable. Dice and session state need JavaScript. Broken avatar assets reveal initials.

The page follows system color preference until a manual light/dark choice is saved locally. Local storage failures do not stop reading or stories. Sessions are replayed through the story engine when restored; stored derived variables are not trusted. Sessions do not synchronize across devices.

## Verification

`npm run check` runs Node's built-in test runner and a validating production build. Tests cover dice rules, limits, branch success/failure, gated choices, replay/restart, malformed saved state, injection, safe URLs, Markdown rendering and homepage counts. Generated output tests cover linked assets, semantic landmarks, local modules and both publications. A separate responsive QA fixture can frame pages at 320, 390 and 768 CSS pixels for browser inspection without adding test tooling to production.

Manual checks before release: inspect the library, a text conversation and the rich demo on desktop/mobile; use keyboard navigation, image dialog, dice controls, story choice/roll/back/restart, theme switching, native media and blocked embed fallback. Native assistive technology and real-device testing remain useful; automated checks are not a certification of universal accessibility.
